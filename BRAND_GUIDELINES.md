# ToneCustoms — Brand & Communication Guidelines

**Brand:** ToneCustoms  
**Positioning:** Independent FiveM script development and interactive roleplay systems  
**Tagline:** **Built for Roleplay. Made with Purpose.**  
**Founder & CEO:** Tone

This guide keeps ToneCustoms consistent across GitHub, documentation, product pages, support messages and demonstrations. It is an internal editorial standard, not a legal trademark or intellectual-property registration.

## Visual identity

- **Primary appearance:** Purple and black, with restrained white or light text for contrast.
- **Typography:** Clear, modern, readable type; prioritize usability over decorative effects.
- **Artwork:** Use the approved ToneCustoms logo and purple brand artwork. Do not replace it with generic GitHub icons or unrelated product marks.
- **Consistency:** Keep banner, logo, storefront and documentation presentation recognizably related.
- **Accessibility:** Maintain readable contrast, meaningful image descriptions and usable mobile layouts.
- **Product media:** Use authentic or clearly labeled preview footage and screenshots; do not imply unimplemented gameplay exists.

### Existing GitHub brand asset

The organization banner is stored at [profile/assets/tonecustoms-header.svg](profile/assets/tonecustoms-header.svg). The profile README references this copy so the organization does not depend on a separate personal repository for its main banner.

## Writing style

- **Professional, direct and specific.** Explain what the script does, which systems it uses, and where to find setup information.
- **Accurate claims.** Clearly distinguish demonstrated, in-development, tested, store-listed and officially released features.
- **Customer-first navigation.** Make About, Updates, Support, Products, Installation and Policies easy to find.
- **No invented assurances.** Do not promise universal framework compatibility, guaranteed response times, lifetime updates, or a fixed release schedule.
- **Consistent names.** Write **ToneCustoms** for the business; use exact resource names such as `tonecustoms_queue` when referring to repositories or FiveM resources.
- **Clear attribution.** Founder and CEO: **Tone**. Do not imply a staffed department or named employee exists solely because a GitHub team was created.

## Public communication checklist

Before publishing or revising a product page, video description or announcement:

1. Confirm product name, scope and supported dependencies.
2. Check whether the product is currently purchasable on the [official store](https://tonecustoms.tebex.store/).
3. Separate confirmed features from planned features.
4. Link to [documentation](https://tonecustoms.github.io/tonecustoms-docs/) and [support](https://discord.gg/JdZ7NTG5KF).
5. Verify that pricing, licensing, refunds and updates do not contradict actual checkout terms.
6. Avoid sharing credentials, customer data, protected code or internal development material.
